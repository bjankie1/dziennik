# Plan 14-03: Role Badge, Connect Screen Selection & Student Message Session (Wave 3)

## Executive Summary
Plan 14-03 completes Phase 14 by finalizing the visual identity of the student role (REQ-ROLE-01, D-01, D-02) and integrating the independent student Librus session for authentic outgoing messages. It adds the visual role badge in `AppDesktopHeader` and `_showProfileSheet`, introduces the role selector (`SegmentedButton<UserRole>`) in `LibrusConnectScreen`, and updates `sendMessage` in `functions/index.js` to dispatch messages using the student's cookie session (`librus_sessions/{studentLogin}`), guaranteeing that teachers receive messages explicitly attributed to *Oskar Jankiewicz (uczeń)*.

---

## Threat Model & Security Controls
<threat_model>
- **Threat T-14-05 (Sender identity confusion / cross-account message impersonation):** A student might inadvertently send a message using the parent's session, misleading school staff.
  - *Mitigation:* The `sendMessage` endpoint checks if the request originates from a user with `role === 'student'`. If so, it requires and utilizes `studentLogin` and the isolated cookie jar from `librus_sessions/{studentLogin}`.
- **Threat T-14-06 (Session pollution across family accounts):** Storing multiple session cookies under a single document could cause overwriting.
  - *Mitigation:* Firestore documents in `librus_sessions` are strictly keyed by individual Librus login identifiers (`librus_sessions/{studentLogin}` vs `librus_sessions/{parentLogin}`).
</threat_model>
