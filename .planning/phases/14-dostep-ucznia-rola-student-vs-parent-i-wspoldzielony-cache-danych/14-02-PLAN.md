# Plan 14-02: Student Justification Request Flow & Parent PIN Approval (Wave 2)

## Executive Summary
Plan 14-02 implements the two-sided parental approval workflow (REQ-ROLE-02, D-03, D-04). The student view in `AttendanceScreen` removes the direct parental submission button and PIN entry, replacing it with a streamlined **„Poproś rodzica o usprawiedliwienie”** flow via `StudentJustificationModal`. Requests are recorded in the `justification_requests` Firestore collection. On the parent's device, incoming requests generate real-time alerts on the Bento Grid dashboard and in the attendance header. The parent reviews the requested hours and reason, authorizes with their 4-digit PIN (`1234`) via `ParentApprovalModal`, and the backend immediately dispatches the official e-Justification to Librus Synergia.

---

## Threat Model & Security Controls
<threat_model>
- **Threat T-14-03 (Unauthorized justification submission without parental PIN):** A student might attempt to directly invoke `submitJustification` without parental consent.
  - *Mitigation:* The `submitJustification` endpoint strictly validates the parent's 4-digit PIN (`1234`). Student requests can only write to `justification_requests` with status `pending_parent_approval`. The transition to `approved` and external dispatch to Librus requires the valid parental PIN.
- **Threat T-14-04 (Double submission / duplicate e-Justification dispatch):** Multiple clicks on approval could flood Librus with duplicated excuse messages.
  - *Mitigation:* The backend marks the request as `processing` or checks `status === 'pending_parent_approval'` atomically before dispatching to Librus, preventing double submissions.
</threat_model>

### Task 14-02-03: Backend endpoints for justification requests & PIN verification
<action>
In `functions/index.js`:
1. Add endpoint `exports.createJustificationRequest`:
   - Validates student authentication/login.
   - Saves document into `justification_requests` collection with status `"pending_parent_approval"`.
2. Add endpoint `exports.reviewJustificationRequest`:
   - Accepts `requestId`, `action` (`"approve"` or `"reject"`), `pin`, and optional `rejectionReason`.
   - For `"approve"`, validates `pin === "1234"` (or user-configured PIN).
   - If valid, calls `LibrusClient.submitJustification` from the parent's session/credentials.
   - Updates document status to `"approved"` (or `"rejected"`).
3. Add endpoint `exports.getJustificationRequests`:
   - Returns requests filtered by `familyId` or `primaryLogin` for the parent or student.
</action>
