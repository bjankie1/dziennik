# Plan 14.1-01: Backend & Domain Layer for Rejection Dialogue & Family Chat (Wave 1)

## Executive Summary
Plan 14.1-01 establishes the foundational data and backend layer for two-way excuse rejection dialogues and real-time family chat between parent and student (REQ-ROLE-04, REQ-CHAT-01). It introduces `ChatMessage` and `JustificationDialogEntry` domain models, extends `JustificationRequest` with `rejectionReason` and `dialogHistory`, and updates Cloud Functions (`reviewJustificationRequest`, `respondJustificationRequest`, `sendFamilyChatMessage`) to record dialog exchanges, enforce role boundaries, and bridge justification rejections directly into family chat cards (D-02).

---

## Threat Model & Security Controls
<threat_model>
- **Threat T-14.1-01 (Family chat cross-tenant leak):** A user could query another family's chat thread by manipulating URL params.
  - *Mitigation:* The chat service enforces scoping strictly under `family_chats/{familyId}/messages`, validating that callers belong to the matching `familyId`.
- **Threat T-14.1-02 (Impersonation in excuse responses):** A student might attempt to directly approve their own rejected request or a parent might attempt to submit student responses.
  - *Mitigation:* `respondJustificationRequest` validates `role === 'student'` and transitions status back to `pending_parent_approval`, while `reviewJustificationRequest` strictly requires `role === 'parent'`.
</threat_model>
