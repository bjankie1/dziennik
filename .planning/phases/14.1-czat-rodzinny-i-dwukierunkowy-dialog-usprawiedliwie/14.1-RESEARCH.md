## 1. Executive Summary

Faza 14.1 rozszerza wdrożony w Fazie 14 model relacji Rodzic ↔ Uczeń o dwa kluczowe elementy:
1. **Dwukierunkowy dialog wokół usprawiedliwień (`REQ-ROLE-04`, `D-02`, `D-03`):**
   - Na kafelku prośby o usprawiedliwienie na Pulpicie (`DashboardScreen`) oraz we Frekwencji (`AttendanceScreen`) dodany zostaje bezpośredni przycisk `[ Odrzuć ]` obok `[ 123 Zatwierdź (PIN) ]`.
   - Kliknięcie `[ Odrzuć ]` otwiera modal `ParentRejectionModal` z polem tekstowym na komentarz lub pytanie do Oskara (np. *„Dlaczego opuściłeś chemię?”*) i szybkimi sugestiami.
   - Komentarz rodzica zapisuje się w dokumencie `justification_requests` w Firestore (`rejectionReason` oraz wpis w tablicy `dialogHistory`).
   - Oskar na swoim koncie widzi powód odrzucenia oraz przycisk `[ Odpowiedz / Poproś ponownie ]`, który pozwala przesłać zaktualizowane wyjaśnienie i przywraca status `pending_parent_approval`.
2. **Wewnętrzny Czat Rodzinny w czasie rzeczywistym (`REQ-CHAT-01`, `D-01`, `D-04`):**
   - Firestore kolekcja `family_chats/{familyId}/messages` z nasłuchem w czasie rzeczywistym (`StreamProvider`).
   - Pełna podstrona `/czat` w menu nawigacyjnym (`AppSidebar`, mobilny pasek dolny) z trasą w `go_router`.
   - Szybki skrót z ikoną czatu i dynamicznym badge'em w nagłówku `AppDesktopHeader` (obok dzwonka powiadomień).
   - Hybrydowe powiązanie: odrzucenie wniosku automatycznie publikuje wiadomość w Czacie Rodzinnym z interaktywną kartą lekcji, z poziomu której Oskar może bezpośrednio odpisać.
   - Dyskretny powiadamiacz SnackBar/Toast w aplikacji w trakcie odbioru nowej wiadomości.

## 2. Architektura i Model Danych

### 2.1. Model `ChatMessage` (`lib/domain/models/chat_message.dart`)

```dart
enum ChatMessageType {
  text,
  justificationCard,
  systemInfo,
}

class ChatMessage {
  final String id;
  final String familyId;
  final String senderId;
  final String senderName;
  final UserRole senderRole;
  final String text;
  final DateTime createdAt;
  final ChatMessageType type;
  final Map<String, dynamic>? metadata;
  final bool isReadByStudent;
  final bool isReadByParent;

  const ChatMessage({
    required this.id,
    required this.familyId,
    required this.senderId,
    required this.senderName,
    required this.senderRole,
    required this.text,
    required this.createdAt,
    this.type = ChatMessageType.text,
    this.metadata,
    this.isReadByStudent = false,
    this.isReadByParent = false,
  });

  Map<String, dynamic> toMap() => {
    'familyId': familyId,
    'senderId': senderId,
    'senderName': senderName,
    'senderRole': senderRole.name,
    'text': text,
    'createdAt': createdAt.toIso8601String(),
    'type': type.name,
    'metadata': metadata,
    'isReadByStudent': isReadByStudent,
    'isReadByParent': isReadByParent,
  };
}
```

### 2.2. Rozszerzenie `JustificationRequest` o historię dialogu

```dart
class JustificationDialogEntry {
  final UserRole senderRole;
  final String senderName;
  final String message;
  final DateTime timestamp;

  const JustificationDialogEntry({
    required this.senderRole,
    required this.senderName,
    required this.message,
    required this.timestamp,
  });
}
```

W modelu `JustificationRequest`:
- `rejectionReason`: String?
- `dialogHistory`: List<JustificationDialogEntry>

### 2.3. Endpointy Cloud Functions (`functions/index.js` & `functions/src/justification_service.js`)

1. `reviewJustificationRequest`:
   - Obsługuje akcję `action: "reject"` z wymaganym polem `reason`.
   - Zapisuje wpis w `dialogHistory` oraz aktualizuje status na `rejected`.
   - Automatycznie tworzy dokument w `family_chats/{familyId}/messages` o typie `justificationCard` z treścią odmowy.
2. `respondJustificationRequest`:
   - Uczeń przesyła dodatkowe wyjaśnienie do odrzuconego wniosku.
   - Aktualizuje status wniosku z powrotem na `pending_parent_approval`.
   - Dodaje wpis ucznia do `dialogHistory` oraz wysyła wiadomość do czatu rodzinnego.
3. `sendFamilyChatMessage`:
   - Rejestruje nową wiadomość w Firestore, ustawiając znaczniki przeczytania.

## 4. Threat Model & Security Controls

<threat_model>
- **T-14.1-01 (Family chat cross-tenant leak):** Wiadomości czatu jednej rodziny nie mogą być odczytane przez inną rodzinę.
  - *Mitigation:* Wszystkie zapytania czatu są bezwzględnie izolowane ścieżką `family_chats/{familyId}/messages`, gdzie `familyId` pochodzi ze zweryfikowanego profilu użytkownika.
- **T-14.1-02 (Impersonation of parent in rejection):** Uczeń nie może sam sobie „odrzucić” lub „zatwierdzić” wniosku.
  - *Mitigation:* Backend `reviewJustificationRequest` sprawdza, czy `role === 'parent'`.
</threat_model>
