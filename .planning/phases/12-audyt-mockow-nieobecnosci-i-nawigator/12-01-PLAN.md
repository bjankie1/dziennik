# Plan 12-01: Audyt mocków, ujednolicenie profilu ucznia i czyste stany puste

**Phase:** 12 — audyt-mockow-nieobecnosci-i-nawigator  
**Plan ID:** 12-01  
**Requirements:** REQ-AUDIT-01  
**Decisions Covered:** D-04, D-05, D-09, D-10, D-11  

---

## 1. Executive Summary

Niniejszy plan eliminuje nieuprawnione fallbacki do `MockData` w trybie zalogowania do Librusa, likwiduje sztuczne dane testowe (mgr K. Wiśniewski, Klasa 3B LO, Liceum KEN, szczęśliwy numerek 9/18 w weekendy), wstrzykuje dynamiczne dane profilu ucznia i wychowawcy (`Sobota Łukasz`) oraz implementuje czyste stany puste (w tym całkowite ukrywanie kafelka sprawdzianu na Pulpicie przy braku zaplanowanych sprawdzianów).

---

- `lib/domain/models/student_profile.dart`:

## 3. Detailed Tasks

### Task 1: Rozszerzenie modelu `StudentProfile` i całkowite odcięcie mocków w `FirestoreSchoolRepository`
- **Pliki:**
  - `lib/domain/models/student_profile.dart`
  - `lib/data/mock/mock_data.dart`
  - `lib/data/repositories/school_repository.dart`
  - `lib/presentation/providers/school_providers.dart`
  - `lib/data/repositories/mock_school_repository.dart`
  - `lib/data/repositories/firestore_school_repository.dart`
- **Kroki implementacji:**
  1. W `StudentProfile` dodać opcjonalne pole `final String? educator;` z parametrem w konstruktorze `this.educator`.
  2. W `MockData.student` ustawić `educator: 'mgr K. Wiśniewski'`.
  3. W `SchoolRepository` zmienić `Future<UpcomingEvent> getUpcomingExam();` na `Future<UpcomingEvent?> getUpcomingExam();`.
  4. W `school_providers.dart` zaktualizować `upcomingExamProvider` na `Future<UpcomingEvent?>`.
  5. W `MockSchoolRepository.getUpcomingExam()` zwrócić `MockData.upcomingExam`.
  6. W `FirestoreSchoolRepository`:
     - W `getStudentProfile()`:
       ```dart
       educator: studentMap['educator'] as String? ?? 'Sobota Łukasz',
       luckyNumber: (data['luckyNumber'] as num?)?.toInt() ?? 0, // zmiana z 9 na 0
       ```
     - W `getUpcomingExam()`:
       ```dart
       final data = await _getStudentData();
       if (data != null) {
         final upcomingExamMap = data['upcomingExam'] as Map<String, dynamic>?;
         if (upcomingExamMap != null) {
           // parse UpcomingEvent
           return UpcomingEvent(...);
         }
         // Brak sprawdzianu w pobranych danych Librus -> zwrot null (D-04, D-05)
         return null;
       }
       return _mockFallback.getUpcomingExam();
       ```
     - W `getScheduleForDay(int dayOfWeek)` oraz `getTodaySchedule()`:
       - Gdy `data != null`, nie wywoływać `_mockFallback.getScheduleForDay(dayOfWeek)` przy pustej liście lekcji (`dayLessons.isEmpty`). Zwrócić pustą listę `[]` (D-05).
     - W `getWeekSchedule({DateTime? weekStart})`:
       - Gdy `data != null`, zwrócić skonstruowaną mapę tygodnia bez wstrzykiwania `_mockFallback.getWeekSchedule()`. Dni wolne mają pustą listę `[]`.
     - W `getSubjects()`, `getRecentGrades()`, `getAttendanceRecords()`, `getAnnouncements()`:
       - Gdy `data != null`, usunąć fallbacki typu `if (validSubjects.isEmpty) return _mockFallback.getSubjects();`. Pusta lista z bazy/API pozostaje pustą listą.
     - W `getTeachers()`:
       - Upewnić się, że `educator` (np. Sobota Łukasz) zawsze trafia na początek listy z rolą `Wychowawca` i id `'educator'`.
- **Weryfikacja:**
  - `flutter analyze` nie zgłasza błędów typowania po zmianie `UpcomingEvent` na `UpcomingEvent?`.

### Task 2: Porządki w `DashboardScreen` — ukrywanie sprawdzianu, numerek w weekendy i dynamiczny kontakt z wychowawcą
- **Pliki:**
  - `lib/presentation/screens/dashboard/dashboard_screen.dart`
- **Kroki implementacji:**
  1. **Ukrywanie karty sprawdzianu (D-04):**
     - W `_buildDesktopScheduleColumn`:
       ```dart

       // dzięki czemu harmonogram płynnie wypełnia całą kolumnę:
       if (exam != null) ...[
         const SizedBox(height: 20),
         _buildUpcomingExamCard(context, exam: exam, ref: ref),
       ],
       ```
     - Usunąć stary zastępczy boks `if (exam == null) Container("Brak zaplanowanych sprawdzianów...")`.
  2. **Obsługa szczęśliwego numerka (D-10):**
     - Zastąpić sztywne `student?.luckyNumber ?? 9`:
       ```dart
       final luckyNumber = student?.luckyNumber ?? 0;
       final showLuckyNumber = !isWeekend && luckyNumber > 0;
       ```
     - Jeśli `isWeekend`:
       - Chip szczęśliwego numerka wyświetla neutralną informację:
         ```dart
         Container(
           padding: const EdgeInsets.symmetric(horizontal: 10, vertical: 5),
           decoration: BoxDecoration(
             color: AppColors.surfaceContainerLow,
             borderRadius: BorderRadius.circular(20),
           ),
           child: const Row(
             mainAxisSize: MainAxisSize.min,
             children: [
               Text("🍀", style: TextStyle(fontSize: 13)),
               SizedBox(width: 6),
               Text(
                 "Brak losowania w weekend",
                 style: TextStyle(
                   fontSize: 12,
                   fontWeight: FontWeight.w600,
                   color: AppColors.onSurfaceVariant,
                 ),
               ),
             ],

         )
         ```
       - Lub jeśli w tygodniu `luckyNumber <= 0`: wyświetla `Brak losowania dzisiaj`.
       - Nigdy nie wyświetlać fikcyjnej liczby 9 ani 18.
  3. **Dynamiczny wychowawca w skrócie kontaktu (D-09):**
     - W kafelku `Kontakt z wychowawcą` w prawym panelu skrótów:
       ```dart

       final homeroomTeacher = teachers.firstWhere(
         (t) => t.role.toLowerCase().contains("wychowawc") || t.subjectName.toLowerCase().contains("wychowawc") || t.id == 'educator',
         orElse: () => teachers.isNotEmpty
             ? teachers.first
             : TeacherContact(
                 id: "educator",
                 name: educatorName,
                 subjectName: "Wychowawstwo",
                 role: "Wychowawca",
                 initials: educatorName.split(' ').map((p) => p.isNotEmpty ? p[0] : '').take(2).join().toUpperCase(),
               ),
       );
       ```
     - Usunąć twardo zakodowane `mgr Krzysztof Wiśniewski`.

  - Test widgetowy `test/dashboard_screen_test.dart` uruchamia się pomyślnie i weryfikuje renderowanie bez błędów.

## 4. Acceptance Criteria & Verification Plan

1. **Brak sprawdzianów (D-04):** Przy pustym terminarzu kafelek "Nadchodzący sprawdzian" na Pulpicie nie jest renderowany w drzewie widgetów, a harmonogram dnia rozciąga się bez zbędnego pustego odstępu.
2. **Odcięcie mocków (D-05):** W trybie z połączonym kontem Librus żaden widok (harmonogram, oceny, frekwencja, nauczyciele) nie pobiera danych testowych z `MockData`. Dni wolne pokazują czysty stan pusty.
3. **Dynamiczny profil i wychowawca (D-09, D-11):** We wszystkich nagłówkach i kartach widoczne są prawdziwe dane: klasa (`4 k Lic`), szkoła (`Liceum Ogólnokształcące nr X im. Stefanii Sempołowskiej`), wychowawca (`Sobota Łukasz`). Frakcje `KEN` i `Wiśniewski` są wyeliminowane z widoków produkcyjnych.
4. **Weekendowy numerek (D-10):** W weekendy chip szczęśliwego numerka informuje o braku losowania („Brak losowania w weekend”) zamiast sztucznej cyfry 9 czy 18.
5. **Jakość kodu:** `flutter analyze` kończy się z wynikiem `No issues found!`.
