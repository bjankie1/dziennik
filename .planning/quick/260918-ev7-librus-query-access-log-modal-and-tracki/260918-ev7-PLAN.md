# Quick Task: Librus Query Access Log Modal & Tracking

Dostęp do dziennika zapytań serwerów Librus w formie access loga z technicznym przyciskiem otwierającym okno modalne.

## User Constraints & Inquiries
- **Access log columns requested by user**:
  - Kiedy (timestamp z dokładnością do sekund)
  - Ile trwało (czas wykonania zapytania w milisekundach)
  - Jaki endpoint (ścieżka Librus, np. `/przegladaj_oceny/uczen`)
  - Jaki wynik (kod HTTP: 200, 302, 429, 503 itp.)
- **Dodatkowe wartościowe metadane (odpowiedź na pytanie użytkownika "coś jeszcze warto?"):**
  - **Typ wywołania (Trigger)**: `Automatyczny (Cron)` vs `Ręczny (Użytkownik)`
  - **Użycie sesji (Session Auth)**: `Ciasteczko sesji` vs `Pełne logowanie OAuth2`
  - **Moduł**: czytelna plakietka modułu (Oceny, Frekwencja, Plan, Wiadomości, Sesja)
  - **Rozmiar odpowiedzi (Size)**: np. 42 KB
  - **Pasek statystyk u góry**: średni czas zapytań, % zapytań 200 OK, stan blokady rate limitu
- **Przycisk otwierający modal**:
  - Wersja desktop (`AppDesktopHeader`): dyskretny przycisk techniczny z ikoną `Icons.terminal_rounded` obok powiadomień z dymkiem "Dziennik zapytań Librus".
  - Wersja mobile (`AppHeader`): przycisk techniczny na pasku górnym.

## Tasks

### Task 1: Backend interceptor, Firestore query logging & HTTP API
- **Pliki:**
  - `functions/src/librus_client.js`
  - `functions/src/sync_service.js`
  - `functions/index.js`
  - `functions/test/librus_query_logs.test.js`
- **Zakres:**
  - Dodanie interceptora w `LibrusClient` mierzącego czas każdego zapytania HTTP i raportującego go przez hook `onQueryLog`.
  - Zapisywanie logów w kolekcji Firestore `librus_query_logs` w `sync_service.js` z informacją o triggerze (`cron` vs `manual`), module, metodzie, statusie i czasie.
  - Dodanie endpointu HTTP `getLibrusLogs` w `functions/index.js` zwracającego ostatnie 50-100 zapytań.
  - Testy jednostkowe potwierdzające rejestrowanie logów.

### Task 2: Frontend Domain Model, Service & Riverpod Provider
- **Pliki:**
  - `lib/domain/models/librus_query_log.dart`
  - `lib/data/services/librus_log_service.dart`
  - `lib/presentation/providers/librus_log_provider.dart`
- **Zakres:**
  - Model `LibrusQueryLog` z parserem `fromJson` i pomocnikami do formatowania czasu, kolorów statusu HTTP i nazw modułów.
  - `LibrusLogService` pobierający dane z backendu (oraz dostarczający przykładowe logi w razie braku połączenia).
  - Riverpod Notifier `librusLogsProvider` zarządzający stanem (ładowanie, odświeżanie, filtry modułów i błędów).

### Task 3: Modal dialog i integracja przycisku w nagłówkach
- **Pliki:**
  - `lib/presentation/widgets/modals/librus_query_log_modal.dart`
  - `lib/presentation/widgets/app_desktop_header.dart`
  - `lib/presentation/widgets/app_header.dart`
- **Zakres:**
  - Implementacja responsywnego okna dialogowego `LibrusQueryLogModal` z kafelkami KPI, filtrami i tabelą logów.
  - Dodanie przycisku technicznego w `AppDesktopHeader` oraz `AppHeader` wywołującego modal.
  - Weryfikacja wizualna i testy `flutter analyze`.
